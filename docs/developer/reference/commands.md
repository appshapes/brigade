# brigade commands

Every command of the `brigade` binary with its usage, the hook, watcher and adapter entrypoints included;
`brigade help --all` prints the same list and `brigade help <command>` the same usage block. Generated by
`make docs-generate` from the command table in `internal/cli/command.go`, and `make docs-check` fails when this
page is stale or when a command is named on no other page, so edit the table, never this page. A command's
own flags are listed as the code registers them; `--json` and `--log-level` apply to every command.

## brigade help --all

```text
Usage: brigade <command> [arguments]

Team messaging between the coding sessions of different people and machines.

Commands:
  version                                     print the version of this binary
  help [command] [--all]                      print usage for the binary or for one command
  sessions [--all] [--here] [--member <who>] [--team <ref-or-name>]
                                              list the team's sessions
  send <session_id> | --member <who> [--summary <text>] [--reply-to <message_id>] [--body-file <path>]
                                              send a message to another session, by its id or its SESSION characters, or to a member's best session (body on stdin)
  whoami                                      print this session's identity
  doing [--clear]                             publish one sentence about what this session is working on (on stdin)
  note                                        record one line about the work for the manager digest — Done:, Next: or Blocked: — in this session's state entry (on stdin)
  decision [--options <a | b>] [--default <option>] [--by <YYYY-MM-DD>] [--card <n>] | --close <id>
                                              ask the project's manager for a decision (the question on stdin), sent at once through a gateway, or close one with its outcome
  report configure --manager <label> [--recipients <@name | #channel | address>] [--every <duration>] [--at <HH:MM>] [--tz <zone>] | show | send
                                              set up the manager digest (reports.json in the state folder), print the digest the producer would send now, or send one now
  inbound [accept|hold|refuse]                show this session's inbound policy, or hold or refuse team messages for this session alone (accept returns to its own policy)
  sync status                                 show the folders this project syncs, the sync engine and the teammates' peers
  team create|join|leave|members|status|reset|revoke-credentials|list|rotate-secret|revoke-member|transfer [--team <ref-or-name>] [adapter flags]
                                              create, join, leave and administer a team, and list its members
  inbox [release] [--session <id>] [--all | <message_id>…] | follow [--incarnation <token>] | read [--cursor <token>]
                                              show and release held messages; follow prints each team message as it lands (a native inbox monitor's command)
  hook session-start|prompt|stop|session-end [--host codex|grok --plugin-root <dir>]
                                              harness lifecycle hook entrypoint (Claude Code, Muse Code, Codex CLI)
  watch [--sink <file> | --host codex]        detached inbound watcher for one session
  adapter <name> <group> <verb> [flags]       run a bundled adapter over the BAP/1 protocol on stdio
  sync-adapter <name> describe|attach|apply|status|detach
                                              run a bundled sync adapter over the sync-adapter protocol on stdio

Global flags:
  --json                                      write the protocol JSON envelope to stdout instead of human output
  --log-level debug|info|warn|error           log verbosity

Run `brigade help <command>` for one command.
```

## brigade sessions

```text
Usage: brigade sessions [--all] [--here] [--member <who>] [--team <ref-or-name>] [--json] [--log-level debug|info|warn|error]

list the team's sessions
```

| Flag | What it does |
| --- | --- |
| `--all` | include offline sessions |
| `--here` | only the sessions of this repository |
| `--member <value>` | only the sessions of one member: their label, or the first 8 or more characters of their principal reference |
| `--team <value>` | the team to act on, by ref or name (terminal only; a session's team comes from its map) |

## brigade send

```text
Usage: brigade send <session_id> | --member <who> [--summary <text>] [--reply-to <message_id>] [--body-file <path>] [--json] [--log-level debug|info|warn|error]

send a message to another session, by its id or its SESSION characters, or to a member's best session (body on stdin)
```

| Flag | What it does |
| --- | --- |
| `--body-file <value>` | read the body from this file instead of stdin |
| `--member <value>` | address a member's best session instead of one session: their label as the MEMBER column shows it, or the first 8 or more characters of their principal reference |
| `--reply-to <value>` | the message id this message answers |
| `--summary <value>` | a one-line summary shown before the body (at most 200 characters) |

## brigade decision

```text
Usage: brigade decision [--options <a | b>] [--default <option>] [--by <YYYY-MM-DD>] [--card <n>] | --close <id> [--json] [--log-level debug|info|warn|error]

ask the project's manager for a decision (the question on stdin), sent at once through a gateway, or close one with its outcome
```

| Flag | What it does |
| --- | --- |
| `--by <value>` | the date an answer is needed by, YYYY-MM-DD |
| `--card <value>` | the card the question belongs to (default `0`) |
| `--close <value>` | close the decision with this id; the outcome travels on stdin |
| `--default <value>` | the option taken when the manager says nothing (one of --options) |
| `--options <value>` | the answers offered, separated by \| |

## brigade report

```text
Usage: brigade report configure --manager <label> [--recipients <@name | #channel | address>] [--every <duration>] [--at <HH:MM>] [--tz <zone>] | show | send [--json] [--log-level debug|info|warn|error]

set up the manager digest (reports.json in the state folder), print the digest the producer would send now, or send one now
```

| Flag | What it does |
| --- | --- |
| `--at <value>` | a daily digest's time of day, HH:MM |
| `--every <value>` | the period between two digests, a duration such as 24h or 4h (24h when unset) |
| `--manager <value>` | the manager's label as the roster shows it |
| `--recipients <value>` | where the digest and the decisions go, in order of precedence, separated by \|: a Slack handle or channel, an email address (the manager's label when left out and it is an address) |
| `--tz <value>` | the zone of --at, an IANA name such as America/Los_Angeles (UTC when unset) |

## brigade inbox

```text
Usage: brigade inbox [release] [--session <id>] [--all | <message_id>…] | follow [--incarnation <token>] | read [--cursor <token>] [--json] [--log-level debug|info|warn|error]

show and release held messages; follow prints each team message as it lands (a native inbox monitor's command)
```

| Flag | What it does |
| --- | --- |
| `--all` | release every held message of the selected sessions |
| `--cursor <value>` | validated continuation from the previous Grok inbox read page |
| `--incarnation <value>` | the exact Grok receiver incarnation (follow only) |
| `--session <value>` | the Brigade session to list or release for (terminal only) |

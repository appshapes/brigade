# make targets

Every target with a help line, in the Makefile's order; `make help` prints the same list. Generated by
`make docs-generate` from the Makefile, and `make docs-check` fails when this page is stale, so edit the
Makefile's `##` comment, never this page. A trailing ` (CI)` marks a target a workflow step runs.

| Target | What it does |
| --- | --- |
| `help` | Show this help message |
| `setup` | go mod download, pinned golangci-lint and goreleaser into ./bin, dev tools, .env scaffold, docker check, push.autoSetupRemote |
| `setup-lint` | Install only the pinned golangci-lint into ./bin (no Docker, no goreleaser) (CI) |
| `setup-goreleaser` | Download the pinned goreleaser release binary into ./bin (release rehearsal only) |
| `version-check` | Fail when the version stamp would be empty (missing or empty plugin/bin/VERSION) |
| `build` | Build bin/brigade plus the dev-only binaries for this host with the release flags (version stamped `<version>-dev`; BRIGADE_COVER=1 adds -cover) (CI) |
| `build-webhook-gateway` | Build bin/brigade-webhook-gateway, the self-hosted webhook gateway, with the release flags |
| `clean` | Remove build artifacts and local caches |
| `typecheck` | go build ./... and go vet ./... (every package, including tests) (CI) |
| `fmt` | gofmt + goimports through golangci-lint |
| `lint` | golangci-lint for darwin AND linux (config verify + run, formatters included) and a plain gofmt check (CI) |
| `lint-fix` | golangci-lint --fix and fmt |
| `test` | Unit + testscript + harness + conformance(fs) with -race; no Docker and no local stack (what `make commit` runs) (CI) |
| `vuln` | govulncheck on the source tree and on the built binary (pinned in tools.mod) (CI) |
| `tidy-check` | Fail if go.mod/go.sum would change (CI) |
| `deps-check` | Fail unless bin/brigade links exactly the modules in docs/allowed-deps.txt (subset, then equality) (CI) |
| `schema` | Regenerate docs/protocol-v1.schema.json from the Go wire types |
| `schema-check` | Fail if docs/protocol-v1.schema.json is stale, empty or ungenerable (CI) |
| `test-db` | pgTAP tests in supabase/tests against the running local stack (CI) |
| `test-integration` | Adapter integration + conformance(supabase) against the local stack (reads $(env_test)) (CI) |
| `test-all` | Everything (requires `make supabase-start supabase-env`) |
| `conformance` | Run the conformance suite against an adapter (usage: make conformance adapter=<executable> [args="-- fixed args"]) |
| `e2e` | Phase 4 no-LLM proof in watcher sink mode against the local stack (CI) |
| `proof` | Phase 4 proof including the headless LLM run, the idle-wake run and the crash-and-resume run (needs a logged-in claude) |
| `harness-smoke` | Headless claude -p smoke test with the fs adapter (needs a logged-in claude; mode=bypassPermissions is card 50's arm, which writes crossSessionInbound accept into your user settings.json) |
| `advisor-lints` | Security Advisor lint mirrors, run with the psql inside the local database container (no host psql needed) (CI) |
| `plugin-check` | Static checks of plugin/: exec-form hooks, no .mcp.json, VERSION == plugin.json, shellcheck, no secrets (CI) |
| `muse-plugin-check` | Static checks of muse/brigade/, the Muse Code package (card 88): allowlist, native manifest, one wrapper per hook, assets equal to plugin/bin's, the marketplace catalog (CI) |
| `muse-digest` | Rewrite marketplace.json's digest and version from muse/brigade/ with Muse (card 115): after any change under muse/brigade/, and by make release |
| `codex-plugin-check` | Static checks of codex/brigade/, the Codex CLI package (card 107): allowlist, native manifest, the three hook commands, the marketplace file, assets equal to plugin/bin's (CI) |
| `docs-check` | The documentation gate (cards 110, 112): README and persona shapes, links and anchors, orphans, harness pages, options, the generated make-target and command pages, a page for every command, the changelog section (CI) |
| `grok-plugin-check` | Validate Grok native package, four hooks, seven skills and canonical release assets (CI) |
| `docs-generate` | Regenerate docs/developer/reference/make-targets.md from this Makefile's help lines and commands.md from internal/cli's command table (docs-check fails when either is stale) |
| `plugin-validate` | claude plugin validate on the marketplace and the plugin root |
| `plugin-dev-pointer` | Write the dev-binary pointer (honours XDG_CONFIG_HOME) without launching anything; a prerequisite of plugin-dev and the manual step of docs/experiments/E3-interactive.md |
| `plugin-dev` | Start Claude Code with the local plugin (usage: make plugin-dev [adapter=fs] [config_dir=<dir>] [mode=default]) |
| `plugin-dev-off` | Remove the local-build pointer so the bootstrap uses the pinned release again |
| `print-version` | Print the version pinned in plugin/bin/VERSION |
| `cross` | Build dist-cross/brigade_$(version)_<os>_<arch> for every target with the exact release flags, plus checksums.txt (CI) |
| `checksums-check` | Fail if plugin/bin/{VERSION,checksums.txt} disagree with plugin.json, a fresh build, or the published release (CI) |
| `release` | Pin the plugin to $(version), commit through the push chain as `$(card): Release $(version)`, tag v$(version) and push the tag (usage: make release version=0.1.0 card=<n> [branch=<throwaway>] — branch only for the P2-12 rehearsal) |
| `release-dry-run` | goreleaser check + a local release without publishing (needs a clean tree and a tag on HEAD) |
| `email-picture` | Capture one picture for the release-notes email into docs/email/$(version)-$(slug).png, 1040 px wide, then print the CHANGELOG line to add (usage: make email-picture version=0.28.0 slug=mail-summary; drag a rectangle) |
| `email-pictures-check` | Check docs/email/ and the CHANGELOG's picture lines against docs/email/README.md's rules (make test runs the same check) |
| `migrations-check` | Fail unless supabase/migrations/ holds at least one .sql file (guards supabase-start; E0-1) |
| `supabase-start` | Start the minimal local stack (db, auth, rest, realtime, kong); applies migrations + seed (CI) |
| `supabase-stop` | Stop the local stack, keep data |
| `supabase-clean` | Stop the local stack and delete its data (CI) |
| `supabase-status` | Show URLs and keys of the running stack |
| `supabase-env` | Write $(env_test) from the running stack, in both name sets (never commit it) (CI) |
| `supabase-reset` | Recreate the local database from migrations + seed |
| `migration-new` | Create supabase/migrations/<timestamp>_$(name).sql (usage: make migration-new name=add_x) |
| `supabase-link` | Link a hosted project -- BROKEN upstream; use backend-install or --project-ref (usage: make supabase-link project=<ref>) |
| `supabase-push-dry` | Show migrations that would be applied to the linked project |
| `supabase-push` | Apply migrations to the linked project |
| `supabase-config-push` | DANGEROUS against a production project -- read the comment above (P5-1); needs i_know=1 |
| `backend-install` | One-shot hosted backend setup (usage: make backend-install project=<ref> [dry=1]) |
| `gateway-install` | Install the hosted mail gateway (usage: make gateway-install project=<ref> from='Name <address>' [team_file=<path to the project's .brigade.json>] [provider=resend\|postmark\|external] [inbox=<address>] [public_address=<address>] [send_url=<url>] [secret_file=<path>] [rotate=1] [dry=1]; needs SUPABASE_ACCESS_TOKEN and RESEND_API_KEY or POSTMARK_SERVER_TOKEN) |
| `gateway-senders` | Show or change who may write to the mail gateway (usage: make gateway-senders project=<ref> [team_file=<path to the project's .brigade.json>] [add='qa@example.com,@example.com'] [remove='<entries>'] [clear=1]; needs SUPABASE_ACCESS_TOKEN) |
| `mail-connector-check` | Check a mail connector's send endpoint (usage: make mail-connector-check send_url=<url> secret_file=<path> [send_to=<address> from='Name <address>']) |
| `slack-gateway-install` | Install the hosted Slack gateway (usage: make slack-gateway-install project=<ref> [team_file=<path to the project's .brigade.json>] [dry=1]; first run prints the manifest, second run needs SLACK_SECRETS_FILE) |
| `functions-check` | Format-check, type-check and unit-test supabase/functions/ with Deno (CI) |
| `pull` | Merge origin into the current branch (plain merge — never rebase; no editor) |
| `commit` | Typecheck, pull, build, test, stage, commit (usage: make commit message="...") |
| `push` | commit + push |

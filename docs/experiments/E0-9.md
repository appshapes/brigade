# E0-9 — `crossSessionInbound` hold and refuse

Date: 2026-08-31 · Ticket 15 · Status: **closed** · Harness: `scripts/experiments/sitting/`
Observed by Rjae at an interactive terminal; frame delivery corroborated from the poster log.

`crossSessionInbound` is a real Claude Code user setting and both `hold` and `refuse` behave as §6.10 assumed. The
experiment documents a limitation rather than changing a decision, and the limitation is sharper than the plan states.

## `hold` — loud, and it does not expire

A Brigade frame posted into a session whose user settings carry `{"crossSessionInbound":"hold"}` produced this
notice, and **no dialog**:

> Held peer message — from an unidentified session; preview: «`<brigade-message team=ops message-id=3c1a7d20-… reply-to-session-id=6f0f2b41-5a3c-49d7-b8e2-0c`» …[6 lines, 1359 chars total — expand to review before approving] — not delivered to Claude (1 held). Your "crossSessionInbound" setting is "hold"; set it to "accept" to deliver held messages.

Four things worth keeping:

- **The message is not delivered** ("1 held"), and no dialog is raised.
- **Nothing expires.** The spec asked whether anything expires after 5 minutes. The session was left held for
  **~25 minutes** and nothing changed at all — no expiry, no release, no prompt, no change to the notice.
- **The notice names its own release path**: *set it to "accept" to deliver held messages*. A held user is not stuck
  without a clue.
- **"from an unidentified session".** A socket post carries no native `from` attribute, so the native layer has no
  name to show. All attribution comes from Brigade's own frame — which is exactly why D19's frame carries
  `from-principal`, `from-name` and `from-label` itself.

The preview truncates the content at roughly 100 characters and reports `[6 lines, 1359 chars total]`, matching the
1361-byte frame that was posted.

## `refuse` — completely silent, in both directions

With `{"crossSessionInbound":"refuse"}`, a frame was posted and **nothing surfaced at all**: no notice, no dialog, no
message, nothing after 15+ seconds of watching.

That silence is a measurement rather than an absence, because the post is independently confirmed:

```
START  16:17:40  claude_pid=16680
POSTED 16:17:48  socket=/tmp/cc-socks/16680.sock  frame_bytes=1361   (0 poster errors)
```

**The sender gets no signal either.** The poster's write *succeeded* — the socket accepted 1361 bytes and returned
nothing, exactly as §6.7 records. So a poster genuinely cannot distinguish "delivered to the model" from "silently
discarded by the harness".

## Why this matters more than "documents the limitation"

This is the empirical basis for two normative statements the plan already makes, and it strengthens both:

1. **`injected` can only ever mean "the frame was written to the session's inbox socket and the connection closed
   without error."** Nothing stronger is claimable, because nothing stronger is observable. §4.5 and §3.x say this;
   E0-9 is the evidence.
2. **§6.10's best-effort settings scan is load-bearing, not defensive.** If Brigade does not notice a native
   `hold`/`refuse` and switch itself to `refuse`, its watcher will **acknowledge messages the harness threw away** —
   the message is gone *and* the sender has been told it arrived. That is silent, unrecoverable loss, and the scan is
   the only thing preventing it. The `hold` policy and `brigade inbox release` remain P5-9.

A useful asymmetry for the docs: `hold` announces itself loudly to the receiving user and tells them how to release;
`refuse` is invisible to everyone. So a user who sets `refuse` and forgets has no reminder, and their teammates have
no way to learn it from the messaging path — which is why `brigade sessions` exposing `inbound=refuse` (4.4, 6.8)
is the only signal senders will ever get.

## Limits

- One observation per policy, on one machine, Claude Code 2.1.251.
- The release path (`hold` → change the setting to `accept` → the held message is delivered) was **not** exercised;
  only the notice's claim that it would work is recorded.
- Both runs used variant A frames in `bypassPermissions`.

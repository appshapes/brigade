## The headline: D20's skill grant holds in interactive Manual mode

This was the open risk to the whole product promise. §6.9 gives the team-messaging skill
`allowed-tools: Bash(brigade:*)`, and D20 claims that once the skill is in play a reply needs no prompt for that
turn — but the plan marks that **verified in `-p` only**. If it failed interactively, a Manual-mode user would be
prompted on every inbound reply and autonomous session-to-session messaging would be dead on arrival.

**It holds.** Three arms, three runs each, in interactive Manual mode with no permission rules at all:

| Arm | Result |
| --- | --- |
| Skill with `allowed-tools: Bash(brigade:*)` | **Zero Bash prompts**, 3/3 — all three commands ran |
| No skill (baseline) | **Prompted**, 3/3 — session stalled at command #1 |
| Skill *without* `allowed-tools` (control) | **Prompted per command**, 3/3 |

The grant **covers the whole turn**, not just the first command — three consecutive Bash calls ran unprompted — and
it **covers write verbs**: the sequence was deliberately read, read, *write* (`brigade sessions`, `brigade whoami`,
`brigade send peer-9 hello-from-skill`) and the write executed unprompted in 3/3. It does **not** extend beyond the
turn: a follow-up asking for `brigade sessions` with no skill in play prompted 3/3, exactly as D20 words it.

### The newly measured cost

**A skill that *declares* `allowed-tools` raises its own one-time Skill-invocation dialog** in Manual mode
("Use skill "brigade:teammsg"? Claude may use instructions, code, or files from this Skill"), 3/3. The
byte-identical control without `allowed-tools` raised no such dialog — so the declaration itself causes it.

So Manual mode costs **one prompt per inbound reply, not one per command**, and the dialog's option 2 retires it
permanently. Two details for the docs:

- **That dismissal is scoped to the project directory** ("don't ask again for `brigade:teammsg` in `<dir>`"), so a
  user pays one approval **per repository**, not once per machine.
- **The declaration and the match do different jobs.** A *mismatched* pattern still raises the Skill dialog; only a
  pattern that *matches* buys the Bash silence. Brigade's skill must therefore declare a pattern covering every
  command form it will actually issue.

The detector was mechanical, not prose: a `PreToolUse` hook fires once the model has produced tool parameters and
*before* the permission decision, while the fake `brigade` appends an exec row only when the command really runs.
Attempt-without-exec plus a stalled session can only be the permission system intervening. Every "unprompted" claim
is backed by a matching exec row, so "did not prompt" is never inferred from an absent dialog.

## (a) First-use download — make the background variant the default

Asset 8,324,402 B (7.94 MiB), served by a Go server pacing writes to an exact rate (measured 999,865 and
250,021 B/s), cold cache every run.

| Rate | SessionStart hook wall time | 20 s bar |
| --- | --- | --- |
| 1 MB/s | **8.49–8.51 s** (3/3) | **passes** |
| 250 kB/s | **33.48 s** (3/3) | **fails** |

Break-evens for this asset: **416 kB/s** for the 20 s bar, 185 kB/s for curl's `--max-time 45`, 139 kB/s for the
hook's 60 s timeout. So the synchronous download *succeeds* at 250 kB/s but blocks session startup for 33 seconds.

The background variant of §6.2 was then built and measured: **the hook returns in 0.019–0.020 s** (5/5), the session
is never blocked, and a detached worker warms the cache 8.36 s / 33.33 s later. **Recommend making it the default.**

These numbers are tied to this asset size — if the shipped binary differs materially, recompute
`bar = size/20`, `curl floor = size/45`, `hook floor = size/60`.

## (c) The sandbox loopback refusal is not an allowlist problem

**Neither `allowedDomains: ["127.0.0.1"]` nor `["localhost"]` lifts the refusal** — and neither does `["*"]`,
`["127.0.0.1:54321"]`, `allowAllUnixSockets`, nor `excludedCommands: ["brigade"]` (2/2 each).

The cause is mechanical and worth knowing precisely: **the sandbox exports `NO_PROXY=localhost,127.0.0.1,::1,…`**, so
a client honouring it dials loopback *directly*, and the direct connect is refused at the sandbox layer
(`dial tcp 127.0.0.1:54321: connect: operation not permitted`, 26/26). When the client is made to ignore `NO_PROXY`
and go through the sandbox's own proxy, **`allowedDomains: ["127.0.0.1"]` works.**

Also measured: the allowlist matches **the literal host as written in the URL**, not a resolved address —
`127.0.0.1` passes for a `127.0.0.1` URL and refuses `127.0.0.2` and `example.com` in the same process.

Consequence for §5.1: the adapter's HTTP client must not honour `NO_PROXY` for loopback inside a sandbox, or it
cannot reach a local stack at all. And `docs/setup.md` should ship the loopback URL using the literal IP the
allowlist entry uses.

## (d) The context line is **not** byte-for-byte the hook's stdout

It is the hook's stdout **trimmed of leading and trailing whitespace**, and nothing else changed.

The authority is the transcript, not the model: Claude Code records the hook fire as an `attachment` carrying *both*
`stdout` (raw bytes) and `content` (the text actually injected), so the comparison is two strings inside one JSON
object. Across 14 runs and 5 deliberately adversarial payloads, `attachment.stdout` equalled the hook's own recorded
bytes 100% of the time, and `attachment.content` equalled `stdout.strip()` 100% of the time. The sharpest case: a
36-byte payload of mixed leading/trailing whitespace around `MID-<nonce>-MID` was injected as the bare 21-byte
middle — **stripped at both ends**, not merely a trailing newline.

Interior formatting survives untouched (blank lines, CRLF, tabs, markdown, curly quotes, em dashes).

## (e), (g) — shadowing and validation

**(e)** With another `brigade` earlier on `PATH`, the `SessionStart` hook printed its shadowing warning **and** the
Bash tool ran the other binary — proven by the decoy recording its own identity, not inferred from output both
binaries could produce.

**(g)** `claude plugin validate ./plugin --strict` **exits 0 with no Claude login** — against a brand-new empty
`CLAUDE_CONFIG_DIR`, and again with a brand-new empty `HOME`, in 0.13–0.155 s. Far too fast for a network call. **It
can join `plugin-check.sh` in CI.**

But with a caveat that changes what that script must do: **validate does not detect a `hooks.json` entry whose
command binary is missing.** A plugin pointing at `${CLAUDE_PLUGIN_ROOT}/bin/does-not-exist` passes with exit 0. So
`scripts/ci/plugin-check.sh` must assert hook-command existence and the executable bit itself.

## (f), (h) — from the same run

**(f)** After `/clear`, `brigade whoami` still resolves through the **unchanged `CLAUDE_PID`**, 3/3. `/clear` is
proven to have fired by a *second* `SessionStart` hook with `source=clear`, and the by-pid map nonce is unchanged
across the boundary — which is the load-bearing evidence, since that nonce exists only in the map file. The Bash
tool's `CLAUDE_CODE_SESSION_ID` rotates to the new native id (recorded, not relied upon).

> **Implementation warning for §6.3.** `SessionStart` **re-fires on `/clear`**. A naive hook re-mints per-session
> state and would rotate the session's Brigade identity on every `/clear`. The probe hook had to be made idempotent
> per pid for this measurement to mean anything; the real hook must be too.

**(h)** A sharp threshold at **exactly 10,000 characters**, bisected to the character: 9,999 and 10,000 succeed
silently; **10,001 fails.** Above it the Bash parser aborts, `Bash(brigade:*)` cannot match, and the call is denied
in `-p` and prompted interactively — **with no "don't ask again" option, so no rule can ever pre-approve it.** That
sets the skill's `--body-file` threshold (§6.9 rule 6) with a margin below 10,000.

## Four method facts worth carrying

1. **Claude Code updated to 2.1.252** mid-experiment. The plan says 2.1.251 throughout.
2. **A fourth first-run prompt exists**: "Claude in Chrome extension detected" (Esc keeps browser tools off). With
   the trust dialog, the fullscreen-renderer write and this, any `expect` driver must tolerate an *arbitrary*
   onboarding prompt.
3. **A trailing `\r` in the same `send` as a long prompt does not submit.** Claude Code treats the fast burst as a
   *paste* and swallows the CR as a newline. Text and Enter must be separate writes with a drain between — this
   silently wasted a first trial, stacking three prompts in the input box.
4. **`SessionStart` re-fires on `/clear`** (see the (f) warning above).

## Honest limits

- **(h)'s exact inclusive edge rests on n=1** at each of 9,999 / 10,000 / 10,001. It is firmly bracketed (three
  successes at or below 9,990, three failures at or above 10,010) but the precise boundary is a single observation.
- **(c) is entirely against a local dev stack over plain HTTP on loopback.** Nothing here tests the hosted project
  over TLS, where the allowlist entry is a real domain and `NO_PROXY` would not match.
- **`sandbox.excludedCommands: ["brigade"]`** did not remove the command from the sandbox with that bare-name value
  (2/2). The correct matcher *form* is unverified, not disproven.
- **The background variant's context line** is not evidenced in the saved artefacts (no transcript captured); the
  string matches the hook source exactly, but that is an inference.
- Two (b) arms and one (f) attempt were **discarded and redone rather than reported** — the (f) attempt asked for a
  command outside `Bash(brigade:*)`, and its dialog ate the `/clear` keystrokes so `/clear` never ran.

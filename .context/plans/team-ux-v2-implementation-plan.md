# Brigade 0.2.0 implementation plan — the project owns the team

Date: 2026-09-06. Ticket 15 (all commits on `master`, messages `15: <Imperative summary>`, `make push message="15: …"`, merges only, never rebase). Status: execution order for the design in `.context/plans/team-ux-v2-proposal.md`. The plan workflow's second verify pass found seven defects (two high, two medium, three low); every fix is applied in this text, marked "verify-round".

## 1. Scope and ground truth

**Ground truth is the brief**: `.context/plans/team-ux-v2-proposal.md` — the proposal, its adversarial review with **all eight fixes adopted**, and the three owner rulings of 2026-09-06 (`--secret-file` mandatory on `team create`; discovery stops at the repository toplevel, always, no `$HOME` fallback; one `team join` verb covering first join and re-consent, with the join secret required for any pin rewrite that changes `adapter`, `url` or `team_ref`). Where this plan and the brief disagree, the brief wins, except for the five mechanical corrections in section 2, which the brief cannot be executed without.

**What ships**: 0.2.0, breaking. Zero users; no migration code; the dead surface is deleted, not hidden. A committed `.brigade.json` (public fields only, closed schema, discovery-never-authority), one-command `brigade team create`, parameterless `brigade team join` with a TTY confirm gate, an attach-only SessionStart hook (repo file → per-checkout pin → `teams/<key>/` credential store, exact refusal lines, zero network on every not-joined path), and the deletion of the user-facing profile concept.

**What is frozen and must not move**: protocol v1. `internal/protocol` (types and Validate), `docs/protocol-v1.md`, `docs/protocol-v1.schema.json`, the conformance suite's cases, `cmd/brigade-adapter-fs`'s wire behavior and the three adapter-direct `fs-*.txtar` files are untouched by every task below. The adapter keeps its profile vocabulary — `--profile <name>` on every command, `profile init/status/reset/revoke-credentials`, `describe.profile.*`, `profile_bound`, `BRIGADE_PROFILE` — and the harness drives it internally with the 32-hex team `<key>` as the profile name. `<key>` passes `adapterkit.CheckProfileName` (`internal/adapterkit/profile.go:93`) with zero code change; that fact is what makes the whole design legal against the frozen protocol, and P7-4 pins it with a test. `docs/protocol-v1.md:812` leaves what a profile file looks like unspecified, so the one on-disk layout rename (P7-3) is not a wire change. The deletions in the brief's §6 are the harness/user surface only.

**The rule-(c) hazard, scheduled deliberately.** The first commit of this plan that changes Go source is the first post-0.1.0 change to the shipped binary's bytes, so `make checksums-check` rule (c) takes its **never-before-run published-release arm**: the committed `plugin/bin/checksums.txt` no longer reproduces from a fresh cross-compile, and CI must fall back to verifying it against the published v0.1.0 release assets (`.context/plans/v0.1.0-followups.md`, "Obligations to watch"). P7-1 is therefore a deliberately small Go change, and its acceptance criteria include watching the `fast` job to completion **before any other task starts**. If that arm is red for an unexpected reason, it is a release-infrastructure bug and fixing it preempts everything else in this plan. No toolchain bump anywhere in this plan: `go.mod`'s `go` line is a release-reproducibility pin and bumping it forces the version bump early.

**Green at every commit.** Every commit builds and passes `make test` (Docker-free; `go test ./...` includes the txtar suite and `internal/harness/e2e`), `make plugin-check` and `make checksums-check`. CI's `supabase` job runs `make e2e` (`scripts/proof.sh`) on every push, so any commit that breaks a proof or smoke script fixes it **in the same commit** — no task below is allowed to leave `scripts/proof.sh`, `proof-headless.sh`, `proof-idle-wake.sh`, `proof-crash-resume.sh` or `harness-smoke.sh` stale across a commit boundary, and their pinning tests (`scripts/ci/proof_test.go` and siblings) move with them. Commits touching `supabase/` or `internal/adapters/supabase` run `make supabase-start supabase-env` once, then `make test-all`, before push. Commits touching a shell file run local shellcheck **and** `docker run --rm -v "$PWD:/mnt" -w /mnt koalaman/shellcheck:v0.9.0 -s sh <file>` (the CI runner has 0.9.0, this machine 0.11, and they disagree). `plugin/.claude-plugin/plugin.json`'s `version` stays `0.1.0` until P7-9's `make release` moves it (`make plugin-check` enforces VERSION == plugin.json). The execution log's Status row for the running task is updated in the same commit as the work.

**Model tiers** (per the log's policy): Fable 5 only where the quality difference matters — the parser, the pins and credential store, the team commands' security logic, the hook's resolution, and every negative security test — each Fable task running one author plus one full adversarial verifier. Opus 5 for the mechanical port, the docs, the CI plumbing and the release. Two security-test rosters land inside Opus tasks for mechanical reasons, and each is explicitly placed under a Fable adversarial verifier's scope so no security test ships unreviewed: P7-1's planted `brg1` scan cases are in P7-2's verifier's mandatory roster, and the terminal-precedence/ambiguity property is authored in P7-5 (Fable), with P7-7 only deleting the bridge (see §4). Verifiers are prompted to assume every pass is for the wrong reason and to demand positive controls.

## 2. Corrections to the brief this plan adopts (do not paper over)

The two inventories found five places where the brief is mechanically wrong or under-specified. Each is settled here so no task re-litigates it:

1. **Re-consent must rewrite the binding, not only the pin.** The brief's §3/§5 say a key-rotation re-consent "writes only the pin", but hook step 3 (§4) verifies `teams/<key>/team.json` against the file on `publishable_key` — a rotation re-consented pin-only mismatches forever (permanent not-joined). Ruling: a publishable-key-only re-consent also drives the adapter's `profile init --force` (documented contract, `internal/adapters/supabase/profile.go:287`: rewrites the backend pair only, never touches `session.json` or the team binding) so pin **and** binding move together. The `<key>` is stable because `publishable_key` is deliberately not in the hash.
2. **A 0644 writer must exist.** `adapterkit.WriteAtomic` hardcodes chmod 0600 (`atomicfile.go:43`) and cannot write `.brigade.json`, which `team create` writes 0644; symmetrically `ReadStrict` refuses group/world-readable files and must not be used to read the repo file. P7-1 adds the mode-taking variant; P7-2 gives the repo file its own reader.
3. **The create temp dir is visible and needs a real prune.** The temp key doubles as `--profile` and `CheckProfileName` forbids a leading dot, so `tmp-<rand>` dirs are visible siblings in `teams/`. Ruling: age-based prune of orphaned `tmp-*` dirs in `team create` and `team list`, with a crash-window test; no hidden-file convention.
4. **The live membership check is `session list`.** The brief's §3 "verifies membership live" names no verb; `team members` needs the optional `team.roster` capability. Ruling: re-consent verifies membership with the core, membership-gated `session list`; if the credential was revoked server-side, fall back to a normal secret join.
5. **`team.json` keeps the adapterkit schema.** The brief's §3 field list omits `version`, which `adapterkit.Profile.Validate` requires. The plan treats the brief's list as informal; the kit schema (including `version` and `SecretStore`) is not forked.

Two further design points the brief leaves open, settled here (Rjae may override before P7-5 lands; both are called out in the log rows):

6. **The fs adapter through the repo file — no schema widening.** `.brigade.json`'s closed schema requires an https/loopback `url` and a `publishable_key`; the fs adapter has neither concept. The parser is **not** made conditional per adapter. A repo file naming `adapter: "fs"` (the e2e rig, the dev loop) carries a loopback placeholder (`http://127.0.0.1:1`) and a placeholder publishable key — public values the fs adapter never reads; the binding stores and verifies them like any other. The closed schema stays closed. Ownership settled (verify-round high fix 1): `profile init --url --key` is **bundled-supabase-conditional** — the extras are Supabase-specific (`docs/protocol-v1.md:98,157`) and the fs adapter's `profile init` accepts only `--force` (`internal/adapters/fs/profilecmd.go:78-80`); for any other dialect the harness runs the adapter's plain `profile init`, and after the adapter child exits `teamstore/write` fills the binding's `adapter`/`url`/`publishable_key` members via `LoadProfile`→`SaveProfile` (the kit schema round-trips them, so later adapter load-modify-saves preserve them). The harness owns those three `team.json` members; the adapter owns everything else it writes.
7. **Non-TTY `team create`/`team join` never read the repo file and stay fully explicit.** With `--profile` dead, the scripted path derives the store key from its own inputs: `url` from the stdin `TeamJoinRequest`'s `backend` member (or `--url` on create), `team_ref` from `JoinSecret.TeamRef()` (or the create RPC's answer), and the adapter name from a new terminal-only `--adapter <name>` flag (default `supabase`, resolved user-side exactly like the file's name). A non-TTY create/join whose cwd sits inside a git checkout writes the pin for that toplevel from those explicit values — never from the file; a poisoned `.brigade.json` in the checkout must not even be opened (P7-5 pins this with a test). Outside a checkout, no pin is written on join — and `team create` in **any** mode refuses outside a checkout (P7-2's discovery answers no-toplevel; a `.brigade.json` written there is a file no discovery could ever find — P7-5).

Also settled: the by-pid map's `profile` member is **renamed** `team_key` (0.2.0 is breaking; a member named `profile` holding a hash is a permanent confusion), with `Validate`'s text, the `map_profile_mismatch` reason token (→ `map_team_key_mismatch`), and lifecycle's "names another profile" log line renamed in the same commit; the watcher env var **keeps** the name `BRIGADE_PROFILE` because its value feeds the adapter's frozen vocabulary. Third-party adapter registration (the deleted `profile init --adapter`'s other job) becomes hand-editing `adapters.json` — the file stays the user-side name registry, `msgUnregistered` is reworded to name it, and `docs/adapter-authors.md` documents the shape; no new verb in 0.2.0. The raw `<key>` is user-visible only in `brigade team list` and DEBUG logs, never in `whoami`.

### P7-2 — `internal/harness/teamfile`: the one shared repo-file parser, discovery and canonicalization

**Builds** (new package; imports only stdlib plus `internal/protocol` — depguard's harness→`internal/adapters/supabase` ban is untouched; **not** in `internal/harness/config`, whose package doc pins it as "the only harness package that reads configuration from the environment" — the repo file is project state read by three callers that must provably share one parser): `internal/harness/teamfile/teamfile.go`, `discover.go`, `teamfile_test.go`, a fuzz test.

### P7-4 — `internal/harness/teamstore`: the team key, the binding, the per-checkout pins

- Read/write split, enforced structurally: writers live in `teamstore/write`; a depguard rule forbids `internal/harness/hook` → `internal/harness/teamstore/write`, so "the hook only reads the store" is a compile-time property, not a convention.

**AC**:

- Binding mismatch refusal per field: four tests (adapter, url, publishable_key, team_ref), each drifting exactly one field and asserting refusal; a fifth asserts `team_name` drift alone does **not** refuse (deliberately unpinned, cosmetic).
